01 · Special Function Registers

A register that isn't just storage — it's a control panel.

Recall 4.3: every peripheral gets addresses inside the same unified memory map as ordinary RAM. A Special Function Register (SFR) lives at one of those addresses, but reading or writing it doesn't just store a number — it directly controls, or directly reflects, real physical hardware. Flip one bit in the right register, and a real pin's voltage changes within nanoseconds. Peripherals typically expose a few different flavors of register for this:

What makes a Special Function Register different from an ordinary SRAM memory location?
The CPU's read/write mechanism is identical either way — that's the whole point of memory-mapped I/O (4.3) — but what's sitting on the other end of that address is completely different: real silicon that reacts, not passive storage.
02 · Bit-Level Register Manipulation

One register, many unrelated settings — so you never touch a byte, only a bit.

A single register often packs together several completely unrelated settings, one per bit — flip the wrong one and you can silently break something else entirely unrelated to what you meant to change. So embedded code almost never assigns a whole register a new value; it surgically sets, clears, or toggles one bit at a time, leaving every other bit exactly as it was.

Set / Clear / Toggle, Live
REG = 0b00000000;
Pick a bit and hit an action — the code line above shows exactly the C idiom real embedded firmware uses to do it, and only that one bit ever changes.
Why does embedded code almost always use `REG |= (1 << n)` instead of just `REG = someNewValue`?
Overwriting the whole register risks silently resetting every other feature that register also controls. Bit-level operations are the safe, surgical way to change exactly one thing.
03 · A Real GPIO Register Set

Three registers, one pin: direction, output, and truth.

The classic, especially clear example (from the AVR family that powers the original Arduino Uno) uses three registers per port: DDR (Data Direction — 1 = output, 0 = input), PORT (when output: the driven level; when input: enables an internal pull-up resistor), and PIN (read-only — the pin's actual, current, real-world voltage, regardless of what you asked for). Every other architecture does the same three-way split with different register names — you'll meet ARM's version in 4.6.

Click a DDR bit to flip that pin between input and output. In output mode, click PORT to drive it high/low — PIN just mirrors it instantly. In input mode, click PIN directly to simulate the outside world (a button, a sensor) changing that pin's real voltage.
A pin is configured as an input, and its DDR bit is 0. What determines the value read back from its PIN register bit?
This is exactly what makes PIN different from PORT: PORT is what you're asking for, PIN is the ground truth of what's actually happening electrically, whether that matches your request or not.
04 · Pin Modes

Every pin has an internal switchboard behind it.

A chip usually has far more internal peripheral signals — UART, SPI, I2C, PWM channels, ADC inputs — than it has physical pins to expose them on. So almost every pin sits behind a tiny internal multiplexer, letting software choose what that pin actually connects to: a plain digital input, a plain digital output, a direct line into the ADC, or one specific peripheral's "alternate function."

One Pin, Four Routes
A single configuration register (Section 01's territory) tells the mux which internal path gets connected to the pin. Switch modes above and watch the routing change.
Why do most microcontroller pins support several "alternate functions" instead of each pin having one fixed job?
Pin count is expensive (bigger package, more board space), so chip designers give you flexibility instead — configure each pin, in software, for whichever one of its several possible jobs you actually need.
05 · Voltage Levels & Logic Thresholds

"0" and "1" are ranges, not exact numbers — and that gap can destroy a chip.

Digital logic doesn't require one exact voltage for "1" and another for "0" — it defines threshold bands. Anything above VIH reads as HIGH, anything below VIL reads as LOW, and the gap between them is deliberately undefined — noise margin, protecting against small voltage wobble. Modern MCUs mostly run at 3.3V logic (ESP32, STM32, Raspberry Pi); the classic 8-bit Arduino Uno runs its logic at 5V. Wire a 5V output straight into a 3.3V-only input and you can exceed its absolute maximum rating — a genuinely common way to quietly kill a chip.

This undefined band isn't a bug — it's intentional noise margin. A real signal should never be allowed to sit in it for long.
Why is it dangerous to connect a 5V-logic device's output pin directly to a 3.3V-only microcontroller's input pin?
Most 3.3V-only chips specify an absolute maximum input voltage not far above 3.3V. A level shifter or resistor divider is the correct fix — never assume "close enough."
06 · Push-Pull, Open-Drain & Pull Resistors

Two ways to output a HIGH — and why one of them refuses to.

A push-pull output actively drives both directions: an internal transistor connects the pin to VCC for HIGH, another connects it to GND for LOW — strong, fast, the default for most GPIO. An open-drain output can only actively pull LOW; for HIGH, it simply releases the pin (goes high-impedance) and relies on a pull-up resistor to passively raise it. This matters enormously on shared buses — I2C (4.7) uses open-drain specifically so multiple devices can share one wire without ever fighting: any device can assert LOW, and the line only floats HIGH when every device lets go.

Push-Pull vs. Open-Drain
Pick Drive HIGH or Drive LOW to see which transistor(s) activate for a push-pull output.
Why does I2C specifically use open-drain outputs instead of push-pull?
If two push-pull outputs on the same wire tried to drive opposite levels, you'd get a direct short between VCC and GND through both chips. Open-drain sidesteps this entirely — the worst case is just "nobody's pulling it low," which the pull-up resolves peacefully.
07 · Beyond Digital: ADC & PWM

The real world is analog. The CPU only speaks in bits.

An ADC (Analog-to-Digital Converter) samples a continuous input voltage and reports back the closest of 2ᴺ discrete digital levels, where N is its resolution. A cheap trick for going the other way — output that behaves analog — is PWM (Pulse Width Modulation): switch a digital pin on and off rapidly, and vary the fraction of time it spends HIGH (the duty cycle) to fake any average voltage you want, without needing a true DAC at all.

How does PWM make an LED appear dimmer without ever outputting a genuine "half-voltage" level?
The pin is only ever fully HIGH or fully LOW — but if it's switching fast enough, neither your eye nor most loads can tell the difference between "actually half voltage" and "full voltage half the time."
