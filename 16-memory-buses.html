01 · Harvard vs. Von Neumann

One memory for everything, or two memories working in parallel?

A Von Neumann machine keeps code and data in one unified memory, reached over one shared bus — simple, but it means the CPU can't fetch the next instruction and read/write data in the same cycle; they queue for the same bus. A Harvard machine keeps program memory and data memory physically separate, often with entirely separate buses — letting the CPU fetch the next instruction and touch data at the same time. Most real microcontrollers use a modified Harvard architecture: separate flash and SRAM, with special instructions available when the program deliberately needs to read flash as if it were data (handy for storing constant lookup tables without eating into precious SRAM).

This parallelism is exactly why most real microcontrollers use a modified Harvard design — it's a meaningful, free speed boost for the fetch-decode-execute loop from 4.2.
02 · The Memory Map

Flash, SRAM, and every peripheral register — one giant numbered list.

Here's the idea that makes 4.4 click: the CPU doesn't really know the difference between "reading a variable from SRAM" and "reading the state of a GPIO pin." Every single thing it can touch — flash, SRAM, and yes, every peripheral's control registers — gets assigned its own address in one unified address space. This is called memory-mapped I/O, and it means controlling real-world hardware is, from the CPU's point of view, indistinguishable from reading or writing a variable.

03 · Three Buses, Three Jobs

Where. What. And how.

The address bus carries only one thing: which location, out of the entire memory map above, the CPU wants to talk to right now. It's one-directional — only the CPU ever drives it. The data bus carries the actual value being moved, and it's bidirectional: sometimes the CPU drives it (writing), sometimes memory or a peripheral drives it back (reading). The control bus is a handful of extra signal lines that settle everything else: is this a read or a write, is the data ready yet, which specific device should even respond.

Why must the data bus be bidirectional, while the address bus almost never is?
Think about what each bus is actually for: "where" only ever comes from the CPU, but "what value" needs to travel in whichever direction the operation demands.

05 · Bus Width & Addressable Memory

Every extra address line doubles the reachable world.

An address bus with N wires can express exactly 2ᴺ distinct patterns — meaning it can address exactly that many unique memory locations, not one more. This is a hard physical ceiling, not a software limitation: a chip with a 16-bit address bus can never address more than 65,536 locations, no matter how the firmware is written. Data bus width is a separate number entirely — it controls how many bits move per single transfer, not how much memory can be addressed at all.

This is exactly why old 16-bit systems topped out around 64KB, and why the jump to 32-bit address buses (4 GB reachable) felt so enormous — each single extra address wire doesn't add a little more room, it doubles the entire space.
A microcontroller has a 12-bit address bus. What's the absolute maximum number of unique memory locations it can ever address?
2¹² = 4,096. This is a hard ceiling baked into the silicon — no clever programming can address a 4,097th location if only 12 address lines physically exist.
