CHAPTER 5.1 · FROM ROCK TO RADIO

Every controller is
a thermostat with opinions.

Real hardware has delay — a sensor takes time to report, an actuator takes time to respond. This module is about what that delay does to a feedback loop that looked perfectly stable on paper.

THE FEEDBACK LOOP · DAMPING · TIME DELAY
01 · The Feedback Loop

Measure, compare, correct, repeat — with real-world lag baked in.

A feedback controller measures the current state, compares it against a target, and pushes a correction proportional to the error — the simplest version, proportional control, is just u = Kp(target − measured). On paper, cranking Kp up always makes the system correct faster. In reality, every sensor and actuator has some delay — and once that delay is in the loop, "faster correction" can start correcting error that's already stale, pushing the system the wrong way entirely.

The exam-relevant takeaway: a controller gain that's stable in simulation (zero delay assumed) can be genuinely unstable on real hardware purely from sensor/actuator lag — this is why control system designers care about phase margin, not just gain margin, and why "just increase Kp" is dangerous advice on a real system.
Increasing Kp on a real (non-zero-delay) control loop makes the correction stronger. Why can this push the system toward instability instead of just making it settle faster?
This is the core reason real control system design can't treat gain tuning in isolation from the plant's actual delay characteristics — a textbook-stable Kp on paper can genuinely oscillate or diverge once real sensor/actuator lag enters the loop.
